# Тест-кейсы AccessEvent

## TC-01. Регистрация пользователя с валидными данными
- Класс данных: валидные
- Предусловия: email не зарегистрирован
- Шаги: POST /api/register (username, email, password, role)
- Ожидаемый результат: 201 Created, user_id в ответе

## TC-02. Регистрация с занятым email
- Класс данных: невалидные (повторно используемые)
- Предусловия: пользователь с email уже существует
- Шаги: POST /api/register с тем же email
- Ожидаемый результат: 400, сообщение об ошибке (не 500!)

## TC-03. Регистрация с email без @
- Класс данных: невалидные
- Шаги: POST /api/register с email "not-an-email"
- Ожидаемый результат: 400, сообщение о неверном формате

## TC-04. Регистрация с коротким паролем
- Класс данных: невалидные (граница пройдена)
- Шаги: POST /api/register с password "Pw1!"
- Ожидаемый результат: 400, сообщение о минимальной длине

## TC-05. Вход с корректными данными
- Предусловия: пользователь зарегистрирован
- Шаги: POST /api/login (email, password)
- Ожидаемый результат: 200, поле token в ответе

## TC-06. Вход с неверным паролем
- Класс данных: невалидные
- Шаги: POST /api/login с чужим паролем
- Ожидаемый результат: 401, без выдачи токена

## TC-07. Создание мероприятия организатором с токеном
- Предусловия: пользователь с ролью organizer, токен получен
- Шаги: POST /api/events с заголовком Authorization: Bearer <token>
- Ожидаемый результат: 201 Created

## TC-08. Создание мероприятия без токена
- Класс данных: негативный (авторизация)
- Шаги: POST /api/events без заголовка Authorization
- Ожидаемый результат: 401 или 403

## TC-09. Регистрация на мероприятие
- Предусловия: мероприятие существует, участник авторизован
- Шаги: POST /api/events/<id>/register с токеном
- Ожидаемый результат: 201, статус регистрации pending

## TC-10. Повторная регистрация на то же мероприятие
- Класс данных: граничные (повторное действие)
- Шаги: POST /api/events/<id>/register дважды с тем же пользователем
- Ожидаемый результат: 400 или 409 — дубль отклонён (UNIQUE-ограничение)

## TC-11. Фильтр инклюзивных мероприятий (инклюзивный кейс)
- Предусловия: в БД есть обычные и инклюзивные мероприятия
- Шаги: GET /api/events?inclusive=true
- Ожидаемый результат: 200, в списке только is_inclusive=true

## TC-12. Цветовая индикация статуса регистрации (инклюзивный кейс)
- Предусловия: регистрация со статусом pending существует
- Шаги: открыть /events и личный кабинет в браузере
- Ожидаемый результат: бейдж pending жёлтый, confirmed зелёный, cancelled красный
